### 1. 视觉目标（Vision）

- **整体风格**：像素风（Pixel Art），强调清晰的像素边缘与统一的色彩与光照逻辑。
- **优先级**：
    1. 像素清晰与一致性（不糊、不抖、不闪）
    2. 可读性（角色与交互对象一眼可分辨）
    3. 反馈（投掷、碰撞、合成、失败等关键事件要有统一的视觉语言）

### 2. 像素与分辨率规范

#### 2.1 像素单位与缩放

- **强制规则**：使用**整数倍缩放**来适配目标分辨率，避免出现半像素导致的抖动与模糊。
- 推荐做法：
    - 采用低分辨率“逻辑视口”（例如 320×180 或 640×360），再整数倍拉伸到窗口分辨率（例如 1920×1080）。
    - 若使用 Camera2D 缩放，Zoom 也应为整数倍。

#### 2.2 纹理过滤与导入

- **强制规则**：纹理过滤使用 **Nearest**，禁止 Linear 过滤导致的模糊。
- 对所有像素资源统一导入预设：
    - Filter: Nearest
    - Mipmaps: 关闭（通常像素风不需要）

### 3. 场景渲染与层级（Layering）

#### 3.1 世界与 UI 分层

- **世界层（World）**：投掷物、容器、障碍物、地面等，受相机与缩放影响。
- **UI 层（UI / CanvasLayer）**：分数、下一颗预览、暂停菜单、结算面板等，不受相机移动影响。

#### 3.2 排序规则

- 为保证可读性，制定统一的排序策略：
    - 背景（最低）
    - 容器/场景结构
    - 投掷物
    - 特效（如合成闪光、粒子）
    - UI（最高）

### 4. 色彩与明暗（Color & Lighting）

- **色彩原则**：少量主色 + 可控的强调色。
- **对比原则**：交互对象与背景保持足够亮度/色相差异，避免“融在一起”。
- **光照原则**：
    - 若使用 2D 灯光（如 PointLight2D），其目的是增强氛围与反馈，而不是破坏像素风的边缘清晰度。
    - 避免过强的动态光造成闪烁与噪点感。

### 5. 事件反馈语言（Feedback Language）

> 这里定义“发生什么事时画面应该怎么响应”。实现可以多样，但口径要一致。
> 

#### 5.1 投掷反馈

- 出生动画：缩放或淡入（短时）
- 预览：半透明或描边，保证与真实实体区分

#### 5.2 碰撞反馈

- 轻碰撞：无或极弱反馈（避免噪音）
- 强碰撞：短促的亮度变化、少量粒子或小幅屏幕震动（可选）

#### 5.3 合成反馈（重点）

- 合成瞬间必须可见：
    - 闪光（短时）
    - 粒子（少量、方向明确）
    - 声音（后续音效文档定义）
- 合成生成物体建议带“软着陆”视觉（与物理策略配套）：
    - 从小到大缩放
    - 轻微弹性 easing（不要夸张）

#### 5.4 失败/结算反馈

- 失败触发：画面降饱和或暗角（可选），并弹出结算 UI。
- 星级/奖励呈现：分段播放（例如星星逐个点亮），节奏可调。

### 6. 资源制作与导出规范（Aseprite / Sprite Sheet）

- 资源制作工具允许多样，但必须满足：
    - 像素对齐
    - 统一调色板（或至少统一色彩策略）
    - 动画帧率与时长可配置
- Sprite Sheet 导出：
    - PNG
    - 必要时附带 JSON 元数据（如帧信息）
    - 统一 Padding，防止渗色

### 7. 常见风险与规避

- **模糊**：Filter 未设为 Nearest 或出现非整数缩放。
- **抖动**：相机或节点位置出现小数像素。
- **遮挡混乱**：未建立稳定的排序规则。
- **反馈过载**：粒子、闪光、震动过多，导致信息噪音。

### 8. 验收标准（Acceptance Criteria）

1. 任意分辨率下，像素边缘保持清晰，不出现明显模糊。
2. 角色与主要交互对象始终可读，不与背景混淆。
3. 合成发生时，玩家能够在 0.3 秒内明确感知（视觉反馈到位）。
4. UI 不随相机移动，且层级始终位于最上。
5. 画面在持续堆叠与频繁合成场景下不闪烁、不抖动。
