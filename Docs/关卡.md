### 1. 关卡系统目标

- 为玩家提供明确的短期目标与渐进式难度曲线。
- 通过**星级评价**提供重复挑战动力。
- 通过 **Season（章节）→ Level（关卡）** 的组织方式支持内容扩展。
- 关卡系统应与：投掷系统、合成系统、分数系统、存档系统低耦合。

### 2. 核心概念与术语

- **Season**：一组主题关卡的集合，带解锁条件。
- **Level**：单个可游玩的关卡实例，包含掉落池、目标与限制条件。
- **Objective（目标）**：关卡完成与星级评价的规则集合。
    - Primary Objective：主目标（决定通关与最低 1 星）
    - Secondary Objectives：副目标（决定额外星级）
- **Stars（星星）**：关卡表现评价（通常 1–3），也是 Season 解锁资源。

### 3. 内容结构与解锁体系

#### 3.1 推荐结构：Season 解锁 + 关卡顺序推进

- **Season 解锁**：使用“总星数”作为解锁资源，达到阈值可解锁新 Season。
- **关卡可玩条件**：建议同 Season 内按顺序推进：
    - Level 1 默认可玩
    - Level N 需要 Level N-1 至少 1 星（可根据需要调整）

#### 3.2 解锁确认弹窗（UX 规则）

- 点击未解锁 Season 时：
    1. 弹出确认对话框（Confirmation Dialog）
    2. 展示：Season 名称、所需星数、当前星数
    3. 若星数不足：给出明确提示，并禁止确认按钮或确认后提示失败
- **对话框必须关联到具体 Season**（避免按钮实例化后丢失上下文）：
    - 推荐：在点击时缓存“当前待解锁 Season 配置”，确认时使用该配置执行解锁。
    - 或：确认对话框组件自身持有配置并在 confirmed 信号里回传。

### 4. 关卡配置（静态数据）设计

> 原则：设计数据与玩家进度数据分离，静态配置只读，动态进度可保存。
> 

#### 4.1 LevelConfig（单关卡）应包含的关键字段

- level_id
- **掉落/生成配置**
    - drop_weights：投掷物类型 → 权重
    - pool_overrides：对象池数量覆盖（可选）
    - default_pool_size：默认池大小（用于未覆盖的条目）
- **目标配置**
    - primary_objective
    - secondary_objectives（数组）
- （可选）规则/限制条件
    - 投掷次数限制
    - 时间限制
    - 容器尺寸/危险线高度
    - 障碍物列表

#### 4.2 SeasonConfig（章节）应包含

- season_id
- season_name
- unlock_stars_required
- levels（按顺序排列）
- total_stars（用于 UI 展示进度，可由 levels 推导或预存）
- season_button_texture（UI 用）

#### 4.3 SeasonCollection / GameProgressConfig

- 统一管理所有 Season 的入口资源，用于选关 UI 构建。

### 5. 玩家进度（动态数据）设计

#### 5.1 存档字段建议

- total_stars：玩家累计星星
- unlocked_seasons：已解锁 Season 列表
- level_progress：关卡进度映射（season_id + level_id → stars / best_score 等）

#### 5.2 星星累计规则

- 同一关卡可重复通关，但只在“本次星级高于历史记录”时增加 total_stars。

### 6. 星级评价（1–3 星）设计

#### 6.1 推荐的星级语义

- **1 星（通关）**：完成主目标。
- **2 星（效率）**：满足一个副目标（例如投掷次数、空间利用率、时间）。
- **3 星（表现）**：满足更严格的副目标（例如高分、连击、零失误等）。

#### 6.2 常见的副目标类型（可组合）

- 最少投掷次数
- 达到分数阈值
- 连续合成次数（连击）
- 容器剩余空间占比
- 不触发危险线/不溢出

#### 6.3 评星计算规则（必须明确）

- 通关后：先判定主目标是否完成。
- 若主目标完成：再逐个判定副目标完成情况。
- 星级 = 1 + 完成的副目标数量（上限 3）。

### 7. 关卡运行时流程（系统交互）

> 这里只描述职责与顺序，不绑定具体脚本写法。
> 
1. 进入关卡：加载 LevelConfig
2. 通知生成系统/对象池按关卡配置准备掉落池
3. 游戏进行中：每次合成/得分事件，更新当前关卡状态，并触发目标检查
4. 失败事件：触发结算（失败原因 + 0 星或按项目定义）
5. 通关事件：计算星级 → 结算 → 写入玩家进度

### 8. 选关 UI 设计要点（实现口径）

- UI 由配置与存档数据驱动生成，不硬编码关卡按钮。
- Season 按钮展示：
    - 名称
    - 解锁状态
    - 星星进度（例如 collected/total）
    - 解锁所需星数
- Level 按钮展示：
    - 关卡编号
    - 已获得星级
    - 锁定状态（不可玩）

### 9. 性能与可维护性约束

- Season/Level 数量较多时：
    - 支持分页或按需加载（只渲染当前页）
    - 支持缓存关卡可玩状态，避免频繁重复计算

### 10. 验收标准（Acceptance Criteria）

1. 配置与存档分离：新增关卡只需要添加配置资源，不需要修改核心逻辑。
2. 星级计算可复验：同一局结算的星级可通过目标规则解释清楚。
3. Season 解锁逻辑可靠：星星足够时可解锁且扣除/消耗规则一致（如有消耗）。
4. 选关 UI 状态正确：锁定、已通关、星级显示与存档一致。
5. 关卡完成后再次进入选关界面，进度刷新正确且无状态丢失。
